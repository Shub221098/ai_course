# Section 7: Vector Databases and Embeddings

> Comprehensive, clear answers for all 26 Vector Database questions.

---

### Q1: What are embeddings in AI engineering?
**Answer:** Embeddings are continuous vector representations (e.g. 768 or 1536 floats) that map text/images into high-dimensional vector space, preserving semantic concepts.

---

### Q2: How do embedding models convert text to vectors?
**Answer:** Embedding models process tokens through Transformer layers and extract the mean pool of final hidden states into a single fixed-size vector.

---

### Q3: What is Contrastive Learning?
**Answer:** Contrastive Learning trains models by pulling matching `(anchor, positive)` text pairs closer in vector space while pushing non-matching `(anchor, negative)` pairs apart using loss functions like InfoNCE.

---

### Q4: Sparse vs Dense Embeddings.
**Answer:**
- **Sparse (BM25 / SPLADE):** Vectors with mostly zeros where indices correspond to specific vocabulary words. Excellent for keyword matching.
- **Dense (OpenAI / bge):** Fully populated non-zero vectors capturing abstract semantic meanings.

---

### Q5: Compare Cosine Similarity, Dot Product, and Euclidean Distance.
**Answer:**
- **Cosine Similarity:** Measures angle between vectors (ignores magnitude).
- **Dot Product:** Measures angle and magnitude ($A \cdot B$). Equals Cosine similarity when vectors are normalized.
- **Euclidean Distance ($L_2$):** Straight-line distance between vector endpoints.

---

### Q6: Vector Database vs Traditional Database.
**Answer:**
- **Traditional DB (SQL):** Optimized for exact key/string matches and relational joins ($O(\log N)$ B-trees).
- **Vector DB (Qdrant/Pinecone):** Optimized for approximate semantic distance search in high-dimensional vector space ($O(\log N)$ HNSW graphs).

---

### Q7: How does Approximate Nearest Neighbor (ANN) search work?
**Answer:** ANN sacrifices 1-2% recall accuracy to build spatial graphs or clusters, avoiding brute-force comparisons against every vector.

---

### Q8: Compare HNSW, IVF, and Flat Indexes.
**Answer:**
- **Flat:** Exact search ($O(N)$). High latency, 100% recall.
- **HNSW:** Multi-layer graph index. Extremely fast, high memory footprint.
- **IVF:** Voronoi cluster index. Low memory usage, slightly lower recall.

---

### Q9: How does an Embedding Cache work?
**Answer:** Caches calculated text-to-vector embeddings in memory (Redis) so identical incoming queries skip expensive embedding API calls.

---

### Q10: How do you choose the right embedding model?
**Answer:** Evaluate on MTEB benchmarks based on task type (retrieval vs classification), vector dimensions, context window, and latency.

---

### Q11: What is embedding dimensionality, and how does it affect cost?
**Answer:** Dimensionality is the vector size (e.g., 384, 768, 1536). Higher dimensions store more semantic detail but increase RAM storage and search latency.

---

### Q12: How to handle embedding drift when embedding models update?
**Answer:** Re-index your document collection using the new embedding model before switching production search traffic.

---

### Q13: What are multimodal embeddings?
**Answer:** Vectors generated by models like CLIP that map images and text into a shared vector space, enabling cross-modal retrieval (text-to-image search).

---

### Q14: How to index and query multi-tenant data in a vector DB?
**Answer:** Use metadata filtering (`tenant_id == X`) during HNSW graph traversal or isolate tenants in separate collections.

---

### Q15: What is embedding quantization (SQ8 / PQ)?
**Answer:** Quantization converts 32-bit floats to 8-bit integers (Scalar Quantization SQ8) or compressed codes (Product Quantization PQ), reducing RAM usage by 75%.

---

### Q16: How to benchmark embedding model quality?
**Answer:** Run evaluation test sets measuring Mean Reciprocal Rank (MRR@k) and Normalized Discounted Cumulative Gain (NDCG@k).

---

### Q17: Role of metadata in vector databases.
**Answer:** Metadata stores structured attributes (author, date, category) attached to vector IDs to enable filtering during search.

---

### Q18: How to scale vector search to billions of vectors?
**Answer:** Use distributed vector DBs, apply Product Quantization (PQ), and shard indexes across multiple nodes.

---

### Q19: What is Hybrid Search?
**Answer:** Combining Sparse BM25 keyword search + Dense Vector search using Reciprocal Rank Fusion (RRF).

---

### Q20: How to fine-tune an embedding model?
**Answer:** Train the model on domain-specific `(query, positive_doc)` pairs using MultipleNegativesRankingLoss.

---

### Q21: Your vector DB is consuming too much RAM. How to fix?
**Answer:** Apply Scalar Quantization (SQ8), reduce embedding dimensions (Matryoshka embeddings), or move index to disk (DiskANN).

---

### Q22: Vector DB cannot scale to millions of embeddings. Fix bottleneck?
**Answer:** Switch from Flat to HNSW/IVF index, add node sharding, and enable memory quantization.

---

### Q23: New embedding model has different dimensions from existing vectors. How to handle?
**Answer:** Re-embed entire corpus in a new collection, run dual-indexing, and cut over traffic when ready.

---

### Q24: Vector search returns irrelevant results despite high similarity scores. How to fix?
**Answer:** Apply re-ranking with a Cross-Encoder, clean noisy documents, and use hybrid search.

---

### Q25: Deployed new embedding model and search quality crashed. Why?
**Answer:** Old document vectors and new query vectors were generated by different models (embedding space mismatch). Re-embed documents.

---

### Q26: Semantic search fails for short queries. How to fix?
**Answer:** Use HyDE (Hypothetical Document Embeddings) to expand short queries before embedding, or add BM25 keyword search.
